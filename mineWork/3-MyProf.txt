### **1. user_settings** (For theme mode & privacy settings)
```sql
CREATE TABLE user_settings (
    user_id UUID PRIMARY KEY REFERENCES users(user_id) ON DELETE CASCADE,
    theme_mode VARCHAR(10) DEFAULT 'light' CHECK (theme_mode IN ('light', 'dark')),
    email_notifications BOOLEAN DEFAULT true,
    push_notifications BOOLEAN DEFAULT true,
    privacy_profile_public BOOLEAN DEFAULT true,
    privacy_show_online_status BOOLEAN DEFAULT true,
    privacy_show_last_seen BOOLEAN DEFAULT true,
    bio TEXT DEFAULT '',
    updated_at TIMESTAMP DEFAULT NOW()
);
```


### **2. blocked_users** (For block/unblock functionality)
```sql
CREATE TABLE user_blocks (
    blocker_id UUID REFERENCES users(user_id) ON DELETE CASCADE,
    blocked_id UUID REFERENCES users(user_id) ON DELETE CASCADE,
    block_reason TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    expires_at TIMESTAMP, -- NULL for permanent
    PRIMARY KEY (blocker_id, blocked_id),
    CHECK (blocker_id != blocked_id),
    INDEX idx_blocks_blocked ON user_blocks(blocked_id)
);
```

### **4. user_search_index** (For efficient search)
```sql
CREATE TABLE user_search_index (
    user_id UUID PRIMARY KEY REFERENCES users(user_id) ON DELETE CASCADE,
    search_vector tsvector,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE
);

-- Create GIN index for fast text search
CREATE INDEX idx_search_vector ON user_search_index USING gin(search_vector);

-- Create trigger to update search_vector
CREATE OR REPLACE FUNCTION update_user_search_index() RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO user_search_index (user_id, search_vector)
    VALUES (
        NEW.user_id,
        to_tsvector('english', 
            COALESCE(NEW.roll_number, '') || ' ' ||
            COALESCE(NEW.user_name, '') || ' ' ||
            COALESCE(NEW.branch, '')
        )
    )
    ON CONFLICT (user_id) 
    DO UPDATE SET search_vector = EXCLUDED.search_vector;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER user_search_trigger 
AFTER INSERT OR UPDATE OF roll_number, user_name, branch 
ON users 
FOR EACH ROW 
EXECUTE FUNCTION update_user_search_index();
```

### **Online Status & Heartbeat**

Since you have `last_seen_at` in your `users` table, use it for the "Offline" state. For the "Online" state, use a Redis cache to avoid heavy DB writes.

1. **Frontend:** On mount, establish a Socket.io connection. Send a `heartbeat` event every 90 seconds.
2. **Backend (Redis):** Set a key `online:{user_id}` with an expiry of 45 seconds.
3. **Frontend (UI):** When fetching a profile, the backend checks Redis:
* **Key exists?** User is 🟢 **Online**.
* **Key missing?** Show "Last seen: `last_seen_at`" from PostgreSQL.
4. **Disconnect:** When the socket closes, the backend performs a **one-time write** to PostgreSQL to update `last_seen_at = NOW()`.

5. **DP (Profile Pic):** Upload to Cloud/S3  Update `dp_url`. Delete old file if it exists
